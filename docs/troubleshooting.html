Troubleshooting

Common issues while configuring, running or changing subject-nsd-plot, and how to resolve them.

Configuration & connections

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to the data the workflow asks for.

The Subject Group Name drop-down is empty

The list loads from the data source chosen under Connect to EarthRanger, so pick that first. If it stays empty, the connection failed or the account can't see any subject groups on that site; check its access in EarthRanger.

The run returns no data

The subject group may have no observations in the chosen time range; widen it, or check in EarthRanger that the group's subjects reported during that period.

Developing

The Subject Group Name field went back to free text

The design was saved from Ecoscope Studio, which rewrote spec.yaml without its rjsf-overrides block. Restore the block (see the Technical Guide) and recompile.

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-subject-nsd-plot-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
