Form overrides

spec.yaml has an rjsf-overrides block that changes the run form:

FieldOverride
subjectgroup_observations.properties.subject_group_nameA drop-down instead of free text. EarthRangerEnumResolver (type: subject_group_name) fills it with the subject group names of the site picked in er_connection (depends_on: properties.er_connection.properties.data_source.properties.name).

Ecoscope Studio's designer doesn't write this block, so spec.yaml is maintained by hand. Saving the design from Studio again replaces the spec and drops the override.

Recompiling

spec.yaml is the source; ecoscope-workflows-subject-nsd-plot-workflow/ is generated from it by wt-compiler. Recompile after changing the overrides: the form schema is part of the generated package.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings. The studio-run case plots the elephants subject group on the MEP-DEV data source, so the machine running it needs that connection.

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh subject_nsd_plot --all
